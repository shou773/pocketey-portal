# Pocketey — Portal

The Astro-built portal site for Pocketey. Hosts game listings, detail pages,
blog and AdSense-required static pages. Each game lives in its own repo at
`../games/<slug>/` and is brought in via `scripts/import-game.mjs`.

## Layout

```
portal/
├── src/
│   ├── content/games/     # generated by import-game.mjs (do not edit by hand)
│   ├── content/blog/      # markdown posts
│   ├── layouts/           # BaseLayout
│   ├── components/        # Header, Footer, GameCard, GameEmbed, AdSlot, NextGameSuggest, SEO
│   ├── pages/
│   │   ├── index.astro            # /  (game grid)
│   │   ├── games/[slug].astro     # /games/<slug>/  (detail + iframe)
│   │   ├── blog/index.astro       # /blog/
│   │   ├── blog/[...slug].astro   # /blog/<slug>/
│   │   ├── about|privacy|contact|terms.astro
│   │   └── rss.xml.ts
│   ├── data/categories.json
│   ├── locales/{en,ja}.json
│   └── utils/             # site, recommend
├── public/
│   ├── games/<slug>/      # generated by import-game.mjs (each contains play/ + thumbnails)
│   ├── og-default.png, icon-{192,512}.png, apple-touch-icon.png
│   ├── manifest.webmanifest, robots.txt, favicon.svg
└── scripts/
    ├── gen-icons.mjs      # generate site icons + default OG
    └── import-game.mjs    # import a finished game build
```

## Develop

```powershell
npm install
npm run dev          # http://localhost:4321
npm run build        # → dist/
npm run preview      # serve dist/ for local QA
```

## Adding a game

1. Build the game (in its own repo): `cd ../games/<slug>; npm run build`
2. From inside `portal/`: `node scripts/import-game.mjs ../games/<slug>/`
3. `npm run build` — the game is now listed on `/`, embedded at `/games/<slug>/`,
   and playable directly at `/games/<slug>/play/`.

The importer validates `game.json` against the required fields. The Astro
Content Collections + Zod schema in `src/content.config.ts` enforces the rest
at build time, so a malformed `game.json` fails the build before deploy.

## Environment variables

| Var | Purpose | Default |
|---|---|---|
| `PUBLIC_SITE_URL` | Used for OGP, canonical, sitemap | `https://pocketey.com` |

Set this in Cloudflare Pages → Project → Settings → Environment Variables for
both Preview and Production.

## Deploy to Cloudflare Pages

### First-time deploy (step-by-step)

1. **Acquire the domain** (`pocketey.com`) at
   [dash.cloudflare.com → Domain Registration](https://dash.cloudflare.com/?to=/:account/domains/register).
   Cloudflare Registrar sells at cost (~$10–15/yr for `.com`). Skip if already
   owned elsewhere — see "Using an external registrar" below.
2. **Create a GitHub repo** (private or public). From this directory:
   ```powershell
   git remote add origin https://github.com/<your-user>/pocketey-portal.git
   git push -u origin main
   ```
3. **Create the Cloudflare Pages project**: dashboard →
   *Workers & Pages → Create → Pages → Connect to Git*. Pick the GitHub repo,
   then on the build settings page:

   | Field | Value |
   |---|---|
   | Framework preset | **Astro** |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | Root directory | (leave blank) |
   | Node.js version | `22.12` or newer (set in *Settings → Environment variables → NODE_VERSION* if the default is older) |
   | Production branch | `main` |

4. **Set environment variables** (*Settings → Environment variables*) for both
   Production and Preview:

   | Variable | Value | Notes |
   |---|---|---|
   | `PUBLIC_SITE_URL` | `https://pocketey.com` | Used for OGP, canonical, sitemap. Omit trailing slash. |
   | `NODE_VERSION` | `22.12` | Only if Cloudflare's default is older. |

5. **Attach the custom domain**: Pages project → *Custom domains → Set up a
   custom domain → `pocketey.com`* (and `www.pocketey.com` if desired). If
   the domain is on Cloudflare Registrar, DNS records are added automatically.
6. **First deploy**: pushing to `main` triggers a build. Watch the *Deployments*
   tab; first build takes ~1–2 min.
7. **Post-deploy verification**:
   - Visit `https://pocketey.com/` and `https://pocketey.com/games/arrow-pop/`
   - Confirm `https://pocketey.com/sitemap-index.xml` lists all pages
   - Submit the sitemap at
     [Google Search Console → Sitemaps](https://search.google.com/search-console)
   - Check `View Source` on a game detail page: `og:image`, canonical, JSON-LD
     should all use the production URL

### Preview deploys

Cloudflare Pages auto-builds every push to non-production branches and every PR.
Preview URLs look like `https://<commit-hash>.pocketey-portal.pages.dev`. Use
this to QA changes before merging to `main`.

### Using an external registrar (e.g. you bought the domain elsewhere)

1. Add the domain in Cloudflare → *Websites → Add site* (free plan is fine).
2. Cloudflare gives you two nameservers — set those at your registrar's panel.
3. Wait for activation (minutes to hours), then attach to Pages as in step 5.

### Adding AdSense / Analytics later

When AdSense and analytics IDs are issued, add them as Pages env vars and the
`<AdSlot>` component will pick them up on the next build:

| Variable | Used by |
|---|---|
| `PUBLIC_ADSENSE_ID` | `<AdSlot>` (display ads on portal pages) |
| `PUBLIC_GA_ID` | (future) GA4 tag |

Cloudflare Web Analytics can be enabled separately from the Pages project's
*Web Analytics* tab — no code change required.
